# R0. 레퍼런스 벤치마크: 함께반 UI 리뷰용 패턴 모음

- 작성: 2026-11-06 / 레퍼런스 벤치마크 담당
- 용도: 디자이너가 구현 중인 "칠판과 분필" 컨셉(paper #FAF7F0, board #1F3D33, chalk yellow #F2C94C, 학년색 blue #4A7FB5 / orange #E07A4F / together #5B9A7D)을 이후 체계적으로 리뷰할 때 쓰는 근거 자료.
- 적용 화면 약어: **한눈에** / **수업 설계** / **타임라인** / **질문함** / **다음 차시** / **학생 페이지**(390px) / **인쇄**

## 0. 출처 표기 규칙 (중요)

화면을 직접 보지 않고 쓴 시각 묘사는 넣지 않았다. 각 출처에 아래 태그를 붙였다.

| 태그 | 의미 |
|---|---|
| **[화면 확인]** | headless Chromium(1440×900)으로 페이지를 띄우고 스크린샷을 직접 봤다. 또는 공식 문서의 스크린샷 이미지를 내려받아 봤다. 시각 묘사는 이 태그가 붙은 것만 쓴다. |
| **[텍스트 확인]** | 페이지 본문 텍스트를 가져와 읽었다. 화면은 보지 못했다. 마이크로카피와 기능 설명만 인용한다. |
| **[스니펫]** | 검색 결과 요약만 봤고 원문을 열지 못했다(차단, 로그인 필요, 404 등). 참고만 할 것. |
| **[자체 실험]** | 함께반 팔레트로 직접 HTML을 렌더해 관찰했다(폰트, 질감, 대비). |

대부분 제품의 **실제 로그인 후 교사 화면은 볼 수 없었다.** 마케팅 페이지, 도움말 스크린샷, 공식 문서 이미지를 기준으로 했다. 로그인 후 화면을 봤다고 쓴 곳은 없다.

## 1. 교사용 에듀테크: 수업안, 실시간 응답판, AI 표시, 승인 흐름

### 1-1. Mentimeter "AI 그룹핑": 군집 카드 그리드 → 클릭하면 원문 [화면 확인]
- 출처: https://help.mentimeter.com/en/articles/8300577-group-responses-to-your-open-ended-questions-using-ai (도움말 본문 스크린샷)
- 본 것:
  - 발표 화면 하단 컨트롤 바에 반짝이(✦) 아이콘이 붙은 **"Show groups"** 알약 버튼이 있다. AI 기능은 아이콘으로만 표시하고 "AI" 글자는 쓰지 않는다.
  - 로딩 상태: 도형 일러스트와 **"Sorting the circles from squares..."** 문구.
  - 결과 화면: 질문 제목 아래 **"✦ 5 groups found"**. 그 아래 **2열 카드 그리드**가 있고, 카드마다 [색 도형 아이콘] + **그룹명**("Positive WFH policy") + **"8 responses"** + **대표 응답 1줄 인용**("Thrilled about new WFH policy!") + 오른쪽 `›`가 들어간다.
  - 카드를 누르면 그룹명과 개수가 헤더에 남고, 원문 응답이 **회색 타일 3열**로 펼쳐진다.
  - 결과 페이지에서는 응답 목록 오른쪽 상단의 작은 ✦ 버튼을 누르면 사이드 패널이 열린다. 패널 문구는 "Use AI to group similar open-ended responses." + 검정 알약 버튼 "✦ Group responses".
  - 텍스트 규칙: 응답이 **10개 이상**일 때만 그룹핑할 수 있다. 그룹명은 수정할 수 있고, 응답을 다른 그룹으로 옮길 수 있고, 새 응답이 들어오면 다시 그룹핑할 수 있다.
- 함께반에 그대로 가져올 것 → **질문함**
  1. 클러스터 카드 = [학년색 점/도형] + 주제명 + "질문 N개" + 대표 질문 1줄 + `›`. 2열 그리드.
  2. 클러스터 목록 위에 "✦ 주제 4개로 묶었어요" 같은 결과 요약 한 줄.
  3. 최소 개수 규칙을 문구로 드러낸다. 예: "질문이 5개 넘게 모이면 묶어 볼 수 있어요"(임계값은 팀이 정한다).
  4. 교사 편집 경로(주제명 고치기, 질문 옮기기, 다시 묶기)를 둬서 AI 결과가 최종이 아님을 보여 준다.

### 1-2. Slido Live Q&A: 투표수 알약, 상위/최신 구분, QR 입장 패널 [화면 확인 + 텍스트 확인]
- 출처: https://www.slido.com/features-live-qa [화면 확인], https://community.slido.com/audience-q-a-42/moderate-and-manage-audience-questions-477 [텍스트 확인]
- 본 것: 발표 화면 왼쪽에 **"Join at slido.com #AllHands"**. 오른쪽 질문 리스트는 "Top questions (18)" / "Latest question" 섹션으로 나뉘고, 질문마다 작성자 이름(또는 Anonymous)이 작게, 질문 본문이 크게, **오른쪽 끝에 "9 👍" 숫자**가 붙는다. 하단 데모 블록은 녹색 카드 안에 **"Join at slido.com" + QR**, 그리고 흰 알약 **"13 👍"**.
- 텍스트로 확인한 모더레이션 상태: **In review → (✓ 승인 / ✕ 보류) → Live → Archive**. 학생 쪽에는 "Waiting for review"가 보인다. 보류한 질문은 복구할 수 있다. 일괄 승인도 있다.
- 가져올 것 → **질문함**, **학생 페이지**
  1. 투사 화면 왼쪽 고정 패널: "칠판에 접속: QR + 짧은 코드". 큰 글씨.
  2. 질문 카드 오른쪽 끝에 "같은 궁금증 N" 숫자 알약. 좋아요 대신 "나도 궁금해" 같은 표현을 쓴다.
  3. 교사 전용 상태 3단계(새로 옴 / 칠판에 띄움 / 보관). 학생 페이지에는 "선생님이 확인하고 있어요" 상태를 보여 준다.

### 1-3. Pear Deck Teacher Dashboard: 교사 화면과 투사 화면 분리, 하단 컨트롤 바 [화면 확인]
- 출처: https://docs.goguardian.com/products/pear-deck/use-the-teacher-dashboard (공식 스크린샷 step-05, step-12를 내려받아 확인)
- 본 것:
  - 왼쪽 슬라이드 썸네일 레일(현재 슬라이드는 노란 테두리), 가운데 큰 응답 미리보기, 오른쪽 상단 "Students" 파란 알약 버튼.
  - **하단 어두운 컨트롤 바**: `‹ ›` / "1 of 1 Responses" / 녹색 점 + "Presenting" / 오른쪽에 "Show Responses", "Lock Screens", "New Prompt", `⋮`, "END".
  - 응답 옆에 ☆ 별표(투사 화면에 강조)와 ⋮ 메뉴(숨기기).
  - Grid view: 연회색 바탕 위에 학생 응답 썸네일 3×3.
- 텍스트로 확인: 투사 화면은 **기본이 익명**이고, 교사 대시보드에서만 이름이 보인다. 숨긴 응답은 대시보드에서 회색으로 남고 삭제되지 않는다. 화면 잠금을 길게 누르면 30초/1분/3분 카운트다운.
- 가져올 것 → **질문함**, **타임라인**
  1. **"교사만 보기 / 칠판에 띄우기" 모드 분리.** 투사 모드에서는 학생 이름을 숨긴다(소규모 학급은 이름만으로 누군지 바로 드러난다).
  2. 진행 중 상태 표시: 녹색 점 + "수업 중 · 18분 경과" 같은 실시간 배지.
  3. 숨긴 질문은 지우지 않고 흐리게 남긴다.

### 1-4. SchoolAI Mission Control: 목표별 분포 막대, 감정 칩, 학생별 AI 요약 [화면 확인]
- 출처: https://schoolai.com/mission-control
- 본 것:
  - 학습 목표 문장("Student can describe the physical characteristics of chameleons.") 아래 **가로 누적 막대 하나**: 빨강 6 / 노랑 2 / 초록 17 / 파랑 2. 숫자가 막대 안에 흰 글씨로 들어간다.
  - 학생 카드: 사진, 이름 "Declan", 주황 칩 **"⚠ Frustrated"**, AI 요약 2~3줄("Declan identifies some traits but is having difficulty connecting them to survival benefits. May need targeted support."), "Outcomes" 아래 색 점 3개.
  - 경고 토스트: 빨간 "⚠ Critical alert" 라벨 + 학생 이름 굵게 + 상황 1줄.
  - 히어로 제목은 핵심 구절("every classroom") 아래에 **노란 손글씨 밑줄**을 한 번만 긋는다. 나머지는 깔끔한 산세리프다.
- 가져올 것 → **다음 차시**, **한눈에**
  1. 성취기준(또는 차시 목표) 한 줄 + **누적 막대 하나**(이해함 / 부분 / 도움 필요). 숫자는 막대 안에 쓴다. 학년별로 막대 2개를 쌓으면 학년 간 비교가 한눈에 된다.
  2. "AI 요약"은 짧게 두세 줄, 끝은 "~할 수 있어요 / 다음 차시에 ~를 권해요" 같은 행동 제안으로 맺는다.
  3. 히어로 핵심어 하나에만 분필 노랑 밑줄(§3-2와 같은 패턴).

### 1-5. Oak National Academy Aila: 좌 대화 / 우 수업안, 섹션 단위 검토 [텍스트 확인 + 랜딩 화면 확인]
- 출처: https://www.gov.uk/algorithmic-transparency-records/oak-national-academy-aila-oaks-ai-lesson-assistant [텍스트 확인], https://labs.thenational.academy/ [화면 확인: 랜딩만]
- 텍스트로 확인:
  - "The user interface displays a chat stream on the left and the lesson output on the right."
  - 수업안을 **섹션별로** 채운다: lesson outcome, prior knowledge, key learning points, misconceptions, keywords, starter quiz, learning cycles, exit quiz.
  - 섹션마다 'modify' 도구가 있고, 프리셋은 더 어렵게 / 더 자세히 / 기타(자유 입력).
  - "intentionally designed not to generate lessons 'at the touch of a button'": 버튼 한 번에 완성본을 내놓지 않도록 일부러 설계했다.
  - 다 완성되면 수업안, 슬라이드, 퀴즈 2개, 워크시트를 내려받는다. 모든 산출물은 편집할 수 있다.
- 랜딩 화면에서 본 것: 연보라 배경의 "Beta" 알약 배지, 마이크로카피 **"with you in control every step of the way"**, 검정 사각 버튼 "Create with AI →".
- 실제 앱 화면은 보지 못했다(로그인 필요, README에도 스크린샷 없음).
- 가져올 것 → **수업 설계**
  1. 수업안을 섹션 카드(목표 / 3학년 활동 / 4학년 활동 / 공통 활동 / 평가)로 나누고, 카드마다 "다듬기 ▾" 프리셋(더 쉽게, 더 짧게, 활동 바꾸기)을 둔다.
  2. 섹션 상태: "AI 초안" → "선생님 확인함 ✓". 모든 섹션을 확인해야 "인쇄/내보내기"가 활성화된다(승인 흐름).
  3. 헤더 마이크로카피: "모든 단계는 선생님이 정해요" 류.

### 1-6. Diffit: 회색 캔버스 위 A4 종이 미리보기 + 섹션 아웃라인 + 상단 변형 툴바 [화면 확인]
- 출처: https://web.diffit.me/updates2025 (임베드 영상의 정지 프레임)
- 본 것: 가운데 **흰 종이 한 장**. 상단에 "Name: ____ Date: ____" 기입란, 이미지, 본문 텍스트. 종이 위 얇은 툴바에 "Reading Length", "Modify Reading", "Change Activity". 왼쪽에 섹션 목록("Reading & Summary / Vocabulary / Multiple Choice Questions / Think Pair Share / +"). 영상 속 강조 표시는 빨간 손그림 사각형이다.
- 텍스트로 확인: "export exactly what you see to Google Docs or Word … or as a print-ready PDF". 화면에 보이는 그대로 내보낸다.
- 가져올 것 → **인쇄**
  1. 인쇄 화면 = 회색(또는 paper 톤보다 어두운) 작업 영역 + 가운데 실제 비율 A4 미리보기. "보이는 그대로 인쇄돼요" 문구.
  2. 종이 상단 "이름: ____ 학년/반: ____" 기입란은 필수.
  3. 왼쪽 섹션 아웃라인(학년별 활동지 1, 2 / 공통)과 `+`.
  4. 종이 위 툴바는 변형 동사 3개 이하(더 쉽게 / 분량 / 활동 바꾸기).

### 1-7. 아이스크림S 홈: 과목 칩 + 학년 숫자, 수업 도구 아이콘 행 [화면 확인]
- 출처: https://www.i-scream.co.kr/
- 본 것: 상단에 **과목 카드 9개**(국어, 도덕, 사회 … 영어). 카드 왼쪽 위에 과목명, **오른쪽 아래에 큰 회색 학년 숫자 "3"**. 오른쪽 로그인 박스 아래 수업 도구 아이콘 4개(알림장 / 판서 / 타이머 / 랜덤 뽑기). 주조색은 주황이고 탭은 주황 채움 알약이다.
- 가져올 것 → **수업 설계**(입력 단계)
  1. 과목·학년 선택 칩에 학년 숫자를 크게 넣는다. 함께반은 칩 하나에 **두 학년 숫자를 학년색으로**("3 · 4").
  2. 교사들이 익숙한 수업 도구 어휘(판서, 타이머, 뽑기)를 그대로 쓴다.

### 1-8. 띵커벨: 교사 홈 = 왼쪽 내비 + 카드형 대시보드, 상태 배지 [화면 확인: 마케팅 목업]
- 출처: https://www.tkbell.co.kr/
- 본 것(마케팅 이미지 속 목업): 왼쪽 내비(홈 / 라이브러리 / 레슨 / 클래스 / 보관함 / 리포트). "나의 수업 리포트" 표는 행마다 [유형 굵게] [하위유형 회색] [제목] [시행일 회색] [상태 배지 "진행"(파랑) / "종료"(회색)]. 주 CTA는 주황 "만들기 +" 하나. 헤더 오른쪽 위에 "방번호 입력"(테두리 주황 글씨).
- 텍스트(기사 스니펫): 2026년 4월 개편 때 "수업 상태를 한눈에 파악할 수 있는 개인 맞춤형 대시보드"를 도입했다. https://view.asiae.co.kr/article/2026041309184158626 [스니펫]
- 가져올 것 → **한눈에**
  1. 최근 수업 표의 행 끝에 상태 배지(설계 중 / 수업 중 / 마침). 배지는 색과 글자를 함께 쓴다.
  2. 학생 입장 동선("방번호 입력")을 헤더에 고정한다. 함께반은 "학생 입장 QR".

## 2. 타임라인/스케줄 UI: 40분 2레인(직접/간접 지도) 타임라인용

### 2-1. Linear Timeline: '오늘' 세로선 + 날짜 칩, 막대 아래 마일스톤 라벨, 초과분 점선 [화면 확인]
- 출처: https://linear.app/docs/timeline (공식 스크린샷 내려받아 확인)
- 본 것:
  - 상단 눈금에 월(MAR, APR…)과 일(19, 26…)이 두 줄로 있고, 세로 점선 그리드가 깔린다.
  - **현재 시점 = 얇은 보라 세로선 + 눈금 위 보라 채움 칩 "JUN 18"**.
  - 프로젝트마다 **제목 줄(아이콘 + 이름 + 상태 아이콘들)이 막대 위에** 있다. 막대는 어두운 둥근 사각형. **마일스톤은 막대 안의 ◇**이고 이름("Beta", "GA")은 **막대 아래 회색 작은 글씨**.
  - **계획보다 늦어지는 구간**은 막대 오른쪽에 **빨간 점선 테두리 + 빨강 그라데이션**으로 이어 붙이고, 위에 "Public Release 12% +3".
- 가져올 것 → **타임라인**
  1. 40분 축 위에 5분 단위 세로 점선, 10분 단위 숫자.
  2. 수업 중 "지금" = 분필 노랑 세로선 + 눈금 위 노랑 칩 "18분".
  3. 활동 블록 제목은 블록 위에 쓰거나, 블록이 좁으면 블록 안 1줄 말줄임. 전환점(모둠 전환, 정리 시작 등)은 ◇ + 아래 작은 라벨.
  4. **규칙 위반 표현**: 시간 초과나 두 학년이 동시에 직접 지도를 받는 겹침은 해당 구간만 점선 테두리 + 경고색으로 칠하고, 위에 "+3분 초과" 같은 숫자 라벨. 블록 전체를 빨갛게 칠하지 않는다.

### 2-2. NLE(Kdenlive) 트랙 구조: 고정 트랙 헤더 + 눈금 + 클립 [화면 확인]
- 출처: https://docs.kdenlive.org/en/user_interface/timeline.html
- 본 것: 왼쪽에 **고정 트랙 헤더 열**(트랙 이름 V1/A1, 잠금·숨김 아이콘), 위에 **시간 눈금**, 그 아래 트랙마다 가로로 클립이 놓인다. 클립은 색 띠와 텍스트 라벨. 문서 텍스트: 트랙 헤더는 트랙 종류, 이름, 잠금 여부를 보여 주고 높이를 따로 조절할 수 있다.
- 가져올 것 → **타임라인**
  1. 레인 = 트랙. 왼쪽 고정 헤더에 "3학년" / "4학년"(학년색 띠 + 학년명). 또는 "직접 지도" / "간접(자기주도)"로 둔다. **헤더를 학년으로 할지 지도 방식으로 할지 하나로 정해야 한다.** 함께반은 레인 2개 = 학년, 블록 채움 방식 = 지도 방식(직접 = 진한 채움, 간접 = 연한 채움/빗금)이 가장 덜 헷갈린다. (팀 결정 사항)
  2. 교사가 직접 지도 중인 블록에는 교사 아이콘(●)을 붙여서, 두 레인에서 ●가 같은 시간에 겹치면 규칙 위반임을 바로 알 수 있게 한다.

### 2-3. Google Calendar: 이벤트 블록 = 색 채움 + 제목 + 시간 범위, 현재 시각 빨간 점선 [화면 확인: 마케팅 일러스트]
- 출처: https://workspace.google.com/products/calendar/
- 본 것: 요일 열 그리드. 이벤트 블록은 색이 채워진 둥근 사각형이고 안에 **제목 1줄 + 시간 범위 1줄**("Focus time / 10 AM – 11 AM"). 현재 시각은 **빨간 점 + 가로선**. 오늘 날짜는 파란 원 안 흰 숫자. 끝난 항목은 취소선("Finalize presentation").
- 텍스트(스니펫): Day view에서 캘린더 여러 개를 나란히 볼 수 있다("View calendars side by side in Day View"). https://discussions.apple.com/thread/254313739 [스니펫]
- 가져올 것 → **타임라인**, **학생 페이지**
  1. 블록 안 2줄 = 활동명 + "0–8분". 블록 높이(또는 폭)가 작아도 이 2줄은 지킨다.
  2. 지난 활동은 흐리게 처리하고 체크를 붙인다. 학생 페이지에서 "지금 할 일"을 강조할 때 쓴다.
  3. "학년별 나란히 보기" = 캘린더 side-by-side와 같은 정신 모델이라 교사에게 설명하기 쉽다.

### 2-4. Pear Deck 하단 진행 바 → 수업 진행 컨트롤 [화면 확인] (1-3과 같은 출처)

## 3. "칠판/교실" 테마를 유치하지 않게 하는 법

Dribbble, Behance, Mobbin에서 "칠판 그린 + 손글씨"로 잘 만든 제품 UI는 **찾지 못했다**(검색 결과 대부분이 스톡 텍스처와 아이콘이었다). 그래서 (a) 손글씨를 절제해서 쓰는 실제 에듀테크 사례와 (b) 함께반 팔레트로 직접 해 본 실험을 근거로 정리했다.

### 3-1. [자체 실험] 한글 손글씨 웹폰트 8종을 #1F3D33 위에서 렌더
- 방법: Google Fonts(Nanum Pen Script, Gaegu, Gamja Flower, Hi Melody, Poor Story, Yeon Sung, East Sea Dokdo, Single Day)와 Pretendard 700을 30px로, 같은 문장("3학년 직접 지도 · 4학년 자기주도 12분")을 #F4F1E8 / #F2C94C로 렌더해 비교했다. 실험 파일은 스크래치패드에 있다(리포 밖).
- 관찰:
  - **Nanum Pen Script, East Sea Dokdo**는 30px로 지정해도 실제로는 약 20px처럼 작게 보인다. 쓰려면 **지정 크기를 1.4~1.5배**로 올려야 한다.
  - **Gaegu, Gamja Flower, Hi Melody**는 자간이 넓게 벌어져 숫자와 단어 경계가 흐려진다. "4학년 자기주도"가 "자기 주 도"처럼 읽힌다.
  - **Poor Story, Yeon Sung, Single Day**는 글자 폭이 고르고 숫자가 잘 읽혀서 **짧은 제목(2~8자)**용으로 무난하다.
  - **Gaegu 17px 본문**은 읽기 피곤하고 자모 굵기가 불균일하다. **본문, 표, 숫자 데이터에 손글씨를 쓰면 안 된다.**
  - Pretendard 700과 비교하면 손글씨는 정보 밀도가 낮다. 타임라인 블록, KPI 숫자, 버튼 라벨은 Pretendard가 맞다.
- 규칙 제안: 손글씨는 **화면당 1~2곳**(페이지 제목 한 단어, 강조 밑줄, 빈 상태 일러스트 문구)에만 쓴다. 숫자와 시간은 항상 Pretendard(tabular-nums).

### 3-2. 손글씨 "밑줄/동그라미"만 쓰고 글자는 산세리프로 [화면 확인]
- 출처: https://classroomscreen.com/ : 히어로 "We're the online **whiteboard** that keeps your students **on task**"에서 "whiteboard"는 청록 손그림 타원, "on task"는 연두 손그림 밑줄. 나머지는 둥근 산세리프.
- 출처: https://schoolai.com/mission-control : "every classroom" 아래 노란 손그림 밑줄 1개.
- 가져올 것 → **한눈에**(히어로), **다음 차시**(핵심 제안 강조)
  - 분필 노랑 #F2C94C SVG 밑줄 또는 동그라미를 **핵심어 하나에만** 쓴다. 글자 자체는 Pretendard. "칠판" 느낌은 이 정도로 충분하다.

### 3-3. [자체 실험] 칠판 질감 강도
- 같은 카드에 fractal noise 질감을 6%와 35%로 올려 비교했다.
- 관찰: 6%는 단색과 거의 구분이 안 되지만 가까이 보면 미세한 결이 있다. 35%는 눈에 띄게 거칠어지고 17px 본문 주변이 지저분해 보인다(스톡 "칠판 텍스처" 느낌).
- 규칙 제안: 질감은 **≤8%**, **큰 board 면(히어로, 투사 화면 배경)에만** 깐다. 카드, 표, 입력창 안에는 깔지 않는다. 나무 테두리, 분필 가루, 지우개 자국 같은 사실적 소품은 쓰지 않는다.

### 3-4. 유치함 경계선 비교 [화면 확인]
- 반례: https://www.toctocmath.kr/ (똑똑수학탐험대): 3D 캐릭터, 로봇, 정글 배경, 무지개색 카드. 학생용으로는 맞지만 **교사용 도구에서는 "장난감" 신호를 준다.**
- 반례: https://padlet.com/ : 일러스트(UFO, 하마, 관람차)가 화면 하단 절반을 채운다. 브랜드 랜딩에는 어울려도 작업 화면 문법은 아니다.
- 기준: Linear(§2-1)와 KRDS(§4)처럼 **작업 화면은 무채색 + 의미색 소수**로 유지하고, 칠판 그린은 "면"(헤더, 투사 모드, 하단 진행 바)으로만 쓴다. 학생 페이지만 캐릭터나 일러스트를 조금 써도 된다.

## 4. 한국 공공/교육 디자인 가이드: KRDS, 토스 UX 라이팅

### 4-1. KRDS 타이포그래피 스케일 [텍스트 확인: 공식]
- 출처: https://www.krds.go.kr/html/site/style/style_03.html (공식), 홈 화면 https://www.krds.go.kr/ [화면 확인]
- 확인한 값(PC / Mobile, 행간은 전부 150%):
  - Display L 60/44, Heading XL 40/28, L 32/24, M 24/22, S 19/19, XS 17/17, XXS 15/15 (700)
  - Body L 19, **Body M 17(기본)**, S 15, XS 13 (400 / 700)
  - 규칙: 본문 **최소 16px**(Pretendard GOV는 작게 나와서 기본 17px). **행간 ≥150%**, 단위는 em/%. 굵기는 400/700 위주로 최대 4단계. 제목:본문 크기 비율 **1.25~1.5배**. 밑줄은 링크에만 쓴다.
  - 대비: AA 일반 4.5:1, 큰 글씨 3:1.
- 가져올 것 → **전 화면**
  - 함께반 기본 본문 17px / 1.5. 보조 15px. **13px은 캡션(눈금 숫자 등) 외에는 쓰지 않는다.**
  - 학생 페이지(390px)도 본문 17px 유지(KRDS도 모바일 본문을 17 그대로 둔다). 제목은 22~24.
  - 타임라인 블록 라벨처럼 공간이 좁은 곳도 15px 아래로 내리지 않는다. 대신 말줄임을 쓰고 툴팁으로 보완한다.

### 4-2. KRDS 컴포넌트 크기, 간격, 포커스 [텍스트 확인: 제3자 정리본]
- 출처: https://www.oppadu.com/tools/design-systems-site/brand/krds.html (**제3자 정리**. 일부 값은 해당 페이지가 스스로 "estimated"라고 표기)
- 값: 간격 기본 8px(4/8/16/24/32/48/64). 버튼 높이 32/40/**48(기본)**/56/64. 입력창 56. 배지 24. radius 4(태그) / 6(버튼) / 8(큰 버튼, 입력) / 12(카드, 모달). 포커스는 2px 흰 안쪽선 + 4px 주조색 바깥 링, `outline:none` 금지. **화면당 채움 주 버튼 1개.** `prefers-reduced-motion`이면 전환 효과를 끈다.
- 가져올 것 → **전 화면**: 주 CTA(분필 노랑 채움)는 화면당 1개, 높이 48. 아이콘 전용 버튼에는 aria-label. 포커스 링은 board 위에서 노랑, paper 위에서 board 색.

### 4-3. KRDS "글자·화면 설정" 진입점 [화면 확인]
- KRDS 홈 헤더 오른쪽 위에 "글자·화면 설정" 링크가 상시 노출된다.
- 가져올 것 → **학생 페이지**: 헤더에 "글자 크게" 토글 하나(저학년, 저시력 학생 대응). 구현 비용이 낮다.

### 4-4. 토스 UX 라이팅 5원칙 [텍스트 확인: 공식 원문]
- 출처: https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md ("UX 라이팅" 절)
- 원문 요지:
  1. **해요체**: "제품 안의 모든 문구는 '해요체'로 써요."
  2. **능동적 말하기**: `됐어요` → `했어요`, '~었' 빼기.
  3. **긍정적 말하기**: "안 돼요, 없어요 (X) → ~하면 할 수 있어요 (O)". 다이얼로그 왼쪽 버튼은 **[닫기]**로 통일한다. "취소"는 작업이 취소된다고 오해할 수 있어서 쓰지 않는다.
  4. **캐주얼한 경어**: '~시겠어요?', '~께' 같은 과도한 경어를 쓰지 않는다.
  5. **'{명사}+{명사}' 쓰지 않기**: 한자어는 풀어 쓴다.
  - 예외: 되어요 → **돼요**로 통일. 부정형이 꼭 필요한 경우(정책상 불가)는 허용.
  - 같은 문서의 CTA 원칙: "CTA 버튼만 보고 다음 행동을 예상할 수 없는 경우"를 치명적 오류로 본다.
- 함께반 적용 예 → **전 화면**
  - "수업안 생성 완료" → "수업안을 만들었어요"
  - "질문 클러스터링 실행" → "비슷한 질문끼리 묶기"
  - "규칙 위반 2건" → "두 학년이 동시에 선생님을 기다리는 구간이 2곳 있어요"
  - "데이터 없음" → "학생이 질문을 보내면 여기에 모여요"
  - 버튼: "확인" 대신 "인쇄 미리보기 열기"처럼 결과가 예측되는 동사.

### 4-5. 당근 SEED [스니펫]
- 2026년 리브랜딩 기사에 "굵기 단계를 세분화해 화면의 위계를 또렷이 했다"는 내용이 있다. https://design.co.kr/article/169523/ [스니펫]. 구체 토큰은 확인하지 못했다. 함께반에는 KRDS 값이 더 직접적인 근거다.

## 5. 심사 데모 화면: 5초 안에 읽히게

### 5-1. 첫 문장은 "무엇을, 누구에게" [텍스트 확인]
- 출처: https://dev.to/kurbaitaev/what-judges-actually-score-notes-from-a-year-of-hackathon-judging-3p4l
- 원문 요지: 좋은 팀은 "this is a tool that does X for Y."라는 평서문으로 시작했다. 맥락부터 길게 설명하면 심사위원이 "a third of the slot without knowing what I was looking at"을 보낸다. "Polish beyond legibility"는 점수를 올리지 않았다. "One complete path through the product beats four half-built paths." 한계를 인정하면 점수가 올랐다. 60초 백업 녹화를 준비하라.
- 가져올 것 → **한눈에**
  - 히어로 1줄: "두 학년이 한 교실에서, 선생님 한 명으로 40분을 나눠 쓰는 수업 설계 도구" 류(대상과 기능을 함께).
  - 데모 경로는 하나만 끝까지: 수업 설계 → 타임라인 규칙 확인 → 질문함 → 다음 차시 → 인쇄.

### 5-2. KPI 타일 = 아이콘 + 큰 숫자 + 짧은 라벨 [화면 확인]
- 출처: MagicSchool "7-10 / hours time saved per week", Brisk 신뢰 배지 3개, Dribbble "Education Dashboard - Teacher View" https://dribbble.com/shots/22276190-Education-Dashboard-Teacher-View (아이콘 + "99% Attendance", "27 Assignments", "Above level 2 / At level 17 / Below level 2")
- 가져올 것 → **한눈에**
  - KPI 타일 3~4개: 숫자는 Pretendard 700, 32~40px. 라벨은 15px 한 줄. 예: "직접 지도 겹침 0곳", "학생 질문 12개 → 주제 4개", "다음 차시 카드 6장", "활동지 2종".
  - 숫자는 **데모 데이터로 계산된 실제 값**이어야 한다(임의 수치 금지).

### 5-3. Before/After 한 쌍 [근거: 일반 원칙, 특정 제품 사례 미확인]
- 검색에서 "before/after 데모 화면" 전용 근거는 찾지 못했다. 다만 Linear의 "계획 대비 초과분을 점선으로 이어 붙이는" 표현(§2-1)과 SchoolAI의 누적 막대(§1-4)는 같은 화면 안에서 차이를 보여 주는 방식이다.
- 제안 → **타임라인**: "규칙 확인 전 / 후" 토글. 전에는 겹침 구간이 점선 경고로 2곳, 후에는 0곳이 되고 블록 위치가 바뀐다. 심사 데모에서 5초 안에 "이 도구가 무엇을 해 주는지" 보여 주는 가장 짧은 장면이다.

## 8. 한계
- 로그인이 필요한 실제 교사 작업 화면(MagicSchool 결과 화면, Aila 편집기, Google Classroom, 하이러닝)은 보지 못했다. 이 문서의 "화면 확인"은 공개 페이지와 문서 이미지 기준이다.
- "칠판 테마를 잘 만든 제품 UI" 실사례는 찾지 못했다. §3은 절제 사례와 자체 렌더 실험으로 대신했다.
- 대비 수치는 WCAG 2.x 상대휘도 공식으로 직접 계산했다. 질감이나 그라데이션 위의 대비는 실제 구현에서 다시 재야 한다.
